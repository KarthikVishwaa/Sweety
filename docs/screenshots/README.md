The desktop shots are 1920x1080 and the mobile ones are 390x844 at twice the pixel density (780x1688). Every file is a palette-
quantised PNG of at most about 500 KB.

## Retaking them

1. Start the app: `npm run db:up`, `npm run db:migrate`, `npm run seed`, then `npm run dev` (the client on port 5173, the API on
   port 4000).
2. Run `npm run screenshots`. To retake only some of them, name them: `npm run screenshots -- 05 11` retakes the groups that hold
   shots 05 and 11 (the group names `login`, `onboarding`, `dashboard`, `profile`, `mobile` and `mobile-onboarding` work too).

What the script does: it refuses to run with `NODE_ENV=production`, checks that both the client and the API answer, starts
Chromium with software WebGL (headless, or with a window if headless cannot draw WebGL) and stops if the 3D canvas comes out
blank. It waits for the network and for the animations to finish, and fails if a toast, a loading skeleton or the Vite error
overlay is on screen. The sign-up shots use throwaway accounts named `shots+<time>@example.com`, and the script deletes every
account matching `shots+%@example.com` when it finishes, even if it failed. Everything else is the published demo account
(`demo@sweety.app`), and nothing is saved on it: the dashboard shots use the newest day with four ordinary readings (70 to 250
mg/dl), and the validation dialog is closed without saving.

The profile shots always show the current month, so they include any unusual readings that have been added to the demo account
since it was seeded.
